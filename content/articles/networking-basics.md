## Модель TCP/IP у чотирьох шарах

- **Канальний (Link)** — Ethernet, Wi-Fi, MAC-адреси.
- **Мережевий (Internet)** — IP-адреси, маршрутизація.
- **Транспортний (Transport)** — TCP (надійний, з підтвердженням) та UDP (швидкий, без гарантій).
- **Прикладний (Application)** — HTTP, DNS, SSH, FTP та інші протоколи, з якими працюють програми.

## Порти — це не магія

Порт — це просто число від 0 до 65535, яке вказує, якій програмі на хості адресований пакет. Кілька орієнтирів, які варто запам'ятати:

| Порт | Протокол | Призначення |
|---|---|---|
| 22 | SSH | Віддалений доступ до shell |
| 53 | DNS | Розв'язання імен у IP-адреси |
| 80 / 443 | HTTP / HTTPS | Веб-трафік |
| 25 | SMTP | Надсилання пошти |
| 3389 | RDP | Віддалений робочий стіл Windows |

Коли інструмент на кшталт nmap каже "порт 22 відкритий", це означає, що на ньому є процес, готовий приймати з'єднання — не більше і не менше.

## DNS у двох словах

DNS перетворює доменні імена на IP-адреси. Атаки на DNS (спуфінг, отруєння кешу) небезпечні саме тому, що весь інтернет неявно довіряє цьому перекладу. З точки зору захисту варто знати про DNSSEC та моніторинг аномальних запитів.

## HTTP: стан немає, а сесія — є

HTTP сам по собі не запам'ятовує стан між запитами. Сесії реалізують поверх нього — через cookies, токени або JWT. Більшість вебатак (XSS, CSRF, session fixation) експлуатують саме цю надбудову, а не сам протокол.

## Що практикувати

Розгорніть у власній ізольованій лабораторії (VirtualBox/VMware, окрема мережа NAT) дві машини та подивіться живий трафік у Wireshark: DNS-запит, TCP-рукостискання, HTTP GET. Побачити пакети наживо — швидший спосіб зрозуміти мережі, ніж будь-який текст.
